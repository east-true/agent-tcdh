# AgentTCDH v0.1.2

Version `0.1.2` brings guided setup and registry management into the CLI. Register connections centrally, discover them over HTTP/MCP/A2A, and execute directly from the consuming environment.

Release preparation is separate from publication. The source version and a locally verified candidate do not establish that an npm version or GitHub release already exists. Check each destination before using published-artifact commands below.

## What is included

- `init`: interactive or automated local/remote setup with reusable defaults and credential variable references.
- Quick registration: inspect remote MCP/A2A metadata or record a stdio command without executing it.
- `connect`: Codex, OpenCode v1/v2, Claude Code, Gemini CLI, Cursor, and VS Code profiles with preview, explicit file merging, and backups.
- `registry import-config` and `preset`: offline-first conversion/selection and explicit atomic registration.
- `doctor` and `doctor --all`: hub access, consumer prerequisites, metadata drift, bounded concurrency, and per-target versions.
- `target edit`, `enable`, and `disable`: file-free management with conditional writes and idempotent no-ops. `target remove --dry-run` reviews a registration before guarded deletion.
- `registry diff` and import/preset `--compare`: read-only differences, retained registrations, and existing import-policy effects.

See [guided setup](../onboarding.md), [client connections](../client-connections.md), [imports/presets](../config-import.md), [management](../target-management.md), and [comparison](../registry-comparison.md) for examples.

## Use a prepared candidate

Requires Node.js 24 or newer. From the verified source checkout, local release preparation writes an installable tarball, `release.json`, and `SHA256SUMS`. For an output directory of `release/v0.1.2`:

```sh
npm install --global ./release/v0.1.2/agent-tcdh-0.1.2.tgz
agent-tcdh --help
agent-tcdh init
agent-tcdh serve
```

The manifest binds the version/tag identity to an exact source commit and tarball checksum. Candidate preparation does not create or push the tag. The [release process](../releasing.md) describes preparation, exact-artifact verification, and the separate publication steps.

The default hub URL is `http://127.0.0.1:3000`, and the default database is `~/.agent-tcdh/registry.sqlite`. Configure credentials before sharing a listener. Setup/client files contain environment names; values belong in the appropriate server or consumer environment.

## Published artifacts

Before installing from npm, verify that it contains the requested version:

```sh
npm view agent-tcdh@0.1.2 version
```

After npm reports `0.1.2`, the published package can be used with `npx --yes agent-tcdh@0.1.2 --help` or installed globally. Before downloading GitHub assets, confirm the `v0.1.2` release exists. Its release workflow verifies the tagged source and exact installable tarball before publication. Publish the exact verified GitHub tarball to npm; do not infer npm availability from a GitHub release.

Verify downloaded `SHA256SUMS` using `sha256sum --check SHA256SUMS` on Linux, `shasum -a 256 --check SHA256SUMS` on macOS, or `Get-FileHash -Algorithm SHA256` on PowerShell. Keep account authentication outside the repository. npm trusted publishing additionally requires package-side trust configuration; the workflow alone does not enable it.

## Compatibility and verification scope

The minimum Node.js version remains 24. SQLite schema version 2, portable snapshot format version 1, HTTP/MCP/A2A contracts, and existing registration data remain compatible. Original full-definition update and deletion commands retain their existing behavior. Invalid UTF-8 snapshot files are now rejected rather than silently replacing malformed bytes.

Native CI covers Linux x64, macOS ARM64/x64, and Windows x64 with regression and isolated production-package checks; independent container CI verifies the Linux runtime and persistence. Release preparation verifies the exact candidate tarball, its manifest/checksums, installed CLI, discovery protocols, management/comparison workflows, and restart persistence.

Client profiles are verified as generated configuration and actual bridge invocations through the MCP SDK. These checks do not establish new native model executions for every client. Earlier public-provider and real-agent evidence retains its original dates and scope; external calls and model runs remain opt-in.

The hub continues to supply metadata. Consumer-side protocol support, selection, credentials, permissions, and execution remain necessary. Registry comparisons are advisory paginated observations; actual imports retain their own conflict transaction and replacement semantics. Disabling a registration changes default discovery visibility and does not revoke provider permissions or cancel existing work.
