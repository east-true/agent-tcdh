# Check a saved client connection

Requires AgentTCDH `0.1.3` or a source checkout containing this command. Version `0.1.2` does not include it. See the [v0.1.3 release notes](releases/v0.1.3.md) for candidate installation and separate publication checks.

After configuring an agent, check whether its saved hub entry still matches the profile generated by the current installation:

```sh
npm run build
node dist/index.js connect codex --check ./client-config.toml
node dist/index.js connect cursor --check ./cursor-mcp.json --json
node dist/index.js connect opencode --check ./opencode.jsonc --hub https://hub.example.com --token-env HUB_READER
```

The explicit file is read locally. The command never writes configuration, creates backups, contacts the hub, launches the bridge, or calls registered targets. It does not choose a personal configuration path. All seven `connect` profiles are supported: `codex`, `opencode`, `opencode-v1`, `claude-code`, `gemini-cli`, `cursor`, and `vscode`.

## Results

| Reason | Meaning | Exit code |
| --- | --- | --- |
| `matched` | The named entry matches this installation's generated profile | 0 |
| `file-missing` | The explicit file does not exist | 1 |
| `entry-missing` | The file exists but the named server entry is absent | 1 |
| `settings-differ` | The named entry differs from the generated profile | 1 |

Malformed files, incompatible containers, invalid UTF-8, symbolic links, and files larger than 1 MiB produce a diagnostic on stderr and exit 1. The source file is preserved.

Output is readable in a terminal, JSON when redirected, or explicitly JSON with `--json`. Reports include the selected client, hub, file path, entry name, reason, and `differingFields`. They never include existing configuration values or arbitrary source field names. Differences are reported by known field names such as `url`, `headers`, `oauth`, `command`, `args`, or `env`. An unexpected field appears as `additional-settings`; a non-object entry appears as `entry`.

The check compares the exact generated entry. Object key order and unrelated settings are ignored. Array order and extra fields on the selected entry matter; a client-specific optional setting can produce a difference even if the client could still connect. Comments, JSONC trailing commas, and JSONC byte-order marks do not affect comparison.

## Select the expected profile

`--hub`, `--token-env`, `--name`, and `--config` have the same meaning as ordinary `connect`. The default entry name is `agent_tcdh`. Hub defaults follow flags, environment, setup configuration, then the built-in local URL. Credential references prefer the setup read reference as usual. The check compares variable names and client placeholder syntax without resolving their values or requiring the variables to be populated in the current shell.

Bridge profiles compare the current Node and package paths as well as arguments and environment references. Moving or reinstalling the package can require regenerating the client entry. A mismatch describes configuration drift; it does not prove the old installation is unavailable.

Use `--check FILE` separately from `--print`, `--write`, `--replace`, and `--dry-run`. To review and apply a correction:

```sh
node dist/index.js connect cursor --print
node dist/index.js connect cursor --write ./cursor-mcp.json --dry-run --replace
node dist/index.js connect cursor --write ./cursor-mcp.json --replace
```

A replacement updates the named entry and keeps an exact backup through the existing configuration writer. Review intentional custom fields before replacing them. The check does not change them automatically.

`matched` verifies local configuration only. It does not verify that the agent loaded the file, has its required environment variables, can authenticate, or can execute a target. Run `doctor` separately to inspect hub access, then use the consuming client to verify its actual behavior. Every check report sets `executionVerified: false`.

To remove a saved entry instead of updating it, use the separate [disconnection preview and apply command](client-disconnection.md). It selects by file and entry name, so stale bridge paths and unavailable hub credentials do not prevent cleanup.
